# opencascade.js — CascadeStudio Fork

This is the `cascadestudio-v2` branch of a fork of [donalffons/opencascade.js](https://github.com/donalffons/opencascade.js). It builds a custom WASM module tailored for [CascadeStudio](https://github.com/zalo/CascadeStudio).

## Build System

The build runs entirely in Docker. The Dockerfile has a multi-stage setup:

1. **base-image** — installs emsdk, Python, libclang, and clones OCCT + dependencies
2. **test-image** — runs binding generation and compilation tests
3. **custom-build-image** — builds a specific YAML config (e.g. `cascadestudio.yml`)

### Build Command

```bash
docker build --target custom-build-image -t ocjs-cascadestudio .
```

Then extract the built artifacts:
```bash
docker create --name ocjs-extract ocjs-cascadestudio
docker cp ocjs-extract:/opencascade.js/dist/ ./dist/
docker rm ocjs-extract
```

The WASM + JS output lands in `dist/` as `cascadestudio.js` and `cascadestudio.wasm`.

## Key Files

| File | Purpose |
|------|---------|
| `builds/cascadestudio.yml` | Binding config — lists every OCCT class/enum to expose |
| `Dockerfile` | Build pipeline — emsdk version, OCCT version, build stages |
| `src/generateBindings.py` | Parses OCCT headers with libclang, generates Embind C++ files |
| `src/compileBindings.py` | Compiles generated .cpp binding files with emcc |
| `src/compileSources.py` | Compiles OCCT source .cxx files with emcc |
| `src/filter/filterMethodOrProperties.py` | Filters which class methods get bindings |
| `src/filter/filterIncludeFiles.py` | Blocklist of headers that cause compilation errors |
| `src/Common.py` | Shared utilities (directory walking, path helpers) |
| `src/flattenOcct8.py` | Flattens OCCT 8.0+ nested `src/Module/Toolkit/Package/` into flat dirs |

## Critical Build Fixes (OCCT RC4 + emsdk 4.0.23)

These fixes are already applied in this branch:

### CONSTRUCTOR macro conflict
emsdk 4.0.23's `val.h` defines a `CONSTRUCTOR` macro that collides with OCCT's `#define CONSTRUCTOR`. Fixed by adding `#undef CONSTRUCTOR` before `#include <emscripten/bind.h>` in `generateBindings.py`.

### Standard_OStream parameter filter
OCCT classes have `DumpJson(Standard_OStream&)` methods. Since ostreams are non-copyable, Embind can't handle them. Fixed in `filterMethodOrProperties.py` by checking parameter types (case-insensitive) for "ostream"/"istream".

### Standard_Integer deprecation
OCCT RC4 deprecates `Standard_Integer` → `int`. This causes `select_overload` template deduction failures in generated bindings. Not fixable per-file — handled by compile tolerance in `compileBindings.py` (try/except around each file).

### OCCT 8.0 directory restructuring
OCCT 8.0 nests source files under `src/Module/Toolkit/Package/File.hxx`. The `flattenOcct8.py` script flattens these back to `src/Package/File.hxx` for compatibility.

### Deprecated directory skipping
`Common.py` skips `/Deprecated` directories when walking OCCT source to avoid binding dead code.

## Adding New Bindings

1. Add the symbol to `builds/cascadestudio.yml` under the appropriate section
2. If the class inherits from a base not yet bound, add the full base class chain
3. For Handle types, add `Handle_ClassName` entries
4. For enums, just add the enum name (e.g. `GeomAbs_CurveType`)
5. Rebuild with Docker

### Embind Inheritance Rules
- Every class in the inheritance chain between a base and derived class must be bound
- Use numbered overloads (e.g. `gp_Pnt_1`, `gp_Pnt_3`) — these are generated by the binding system
- Handle types need explicit entries: `Handle_Geom_Curve` becomes `Handle_Geom_Curve_2` for the upcasting constructor

## Binding YAML Structure

```yaml
mainBuild:
  name: cascadestudio.js     # Output filename
  bindings:
    - symbol: ClassName       # Each OCCT class/enum to bind
  emccFlags:
    - "-O3"                   # Compiler flags for the final link
additionalCppCode: |          # Extra C++ injected into bindings
  class OCJS { ... };
```

## Troubleshooting

- **"Cannot construct X due to unbound types"** — A constructor parameter type isn't bound. Add it to the YAML.
- **"select_overload" errors** — Usually `Standard_Integer` deprecation. The compile tolerance handles this.
- **Handle type mismatch** — Ensure the Handle entry uses the correct numbered overload suffix.
- **Build hangs on one file** — Individual binding file compilation has a tolerance mechanism; failed files are skipped with a warning.
